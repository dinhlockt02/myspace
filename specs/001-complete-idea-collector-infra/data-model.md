# Data Model: Idea Collector

This document defines the data structures and storage schema for the Idea Collector application.

## DynamoDB Table: `IdeaCollector_Ideas`

### Schema

- **Partition Key**: `id` (String) - A unique UUID (v4) generated by the ingestion backend.
- **Sort Key**: None

### Attributes

| Attribute Name | Type | Description | Required | Constraints |
|----------------|------|-------------|----------|-------------|
| `id` | String | Unique identifier | Yes | UUID v4 |
| `idea` | String | The text content of the idea | Yes | 1 to 5,000 characters |
| `client_timestamp` | Number | Timestamp provided by the frontend client (Unix time ms) | Yes | Valid epoch time |
| `server_timestamp` | Number | Timestamp recorded by the ingestion service upon receipt (Unix time ms) | Yes | System time at ingestion |

### State Transitions

- Ideas are strictly immutable (append-only) in v1. No updates or deletions are supported via the public API.

## Validation Rules

- The `idea` text must not be empty and must not exceed 5,000 characters (FR-008).
- The `client_timestamp` must be present and parseable as a valid number/date.
- Submissions failing these rules will be rejected with a `400 Bad Request` and an appropriate error message.
