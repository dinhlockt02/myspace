# Implementation Plan: Post-Implementation PR Management Skills

**Branch**: `007-manage-pr-workflow` | **Date**: 2026-10-12 | **Spec**: [specs/007-manage-pr-workflow/spec.md](spec.md)

**Input**: Feature specification from `specs/007-manage-pr-workflow/spec.md`

## Summary

Implement an automated post-implementation Pull Request (and Merge Request alias) management suite for the Myspace monorepo. The solution follows the established repository dual-mode architecture: a modular root CLI script (`scripts/pr-workflow.sh` with helper libraries in `scripts/lib/` accessible via `pnpm run pr`) for direct terminal/CI execution, and a companion AI agent skill (`.agents/skills/speckit-pr/SKILL.md`) for conversational interaction in the Antigravity IDE. The workflow executes pre-flight quality gates (git working tree cleanliness, Nx affected project linting and tests, secret leak auditing), pushes local commits with upstream tracking, synthesizes structured PR titles and bodies adhering to Monorepo Constitution Principle I (Intent, Scope, Completed Tasks, Verification Steps, Pre-Flight Gates), opens or updates GitHub Pull Requests via dual communication channels (prioritizing `gh` CLI with transparent `GITHUB_TOKEN` REST API fallback), and provides status inspection for CI/CD checks and merge readiness.

## Technical Context

**Language/Version**: Bash 5+, Node.js 20+

**Primary Dependencies**: `git`, GitHub CLI (`gh`), `curl`, `pnpm` (>= 9.0.0), Nx (>= 20.0.0)

**Storage**: Remote GitHub API for Pull Request resources; local git repository and working tree for change detection

**Testing**: Pre-flight verification scripts, shell validation tests, and end-to-end quickstart scenarios in [quickstart.md](quickstart.md)

**Target Platform**: Linux, macOS, Windows WSL

**Project Type**: Developer CLI Tool, Shell Libraries, and Spec-Kit AI Agent Skill

**Performance Goals**:
- Pre-flight quality gate evaluation completed in < 15 seconds
- End-to-end PR creation or update completed in < 30 seconds
- Status query inspection completed in < 5 seconds

**Constraints**:
- Strict adherence to Monorepo Constitution Principle I: every PR must have clear Intent, Scope, and Verification Steps
- Zero committed credentials or sensitive tokens (enforced via local pre-flight secret audit)
- Default to Draft mode on initial creation to permit author inspection before team review notifications
- Idempotent execution: invoking create on a branch with an open PR updates the existing PR without duplicate generation
- Dual communication channels: prioritize `gh` CLI, fall back gracefully to direct GitHub REST API with `GITHUB_TOKEN`

**Scale/Scope**: Repository-wide developer workflow applicable to all monorepo applications (`apps/*`), shared packages (`packages/*`), and infrastructure code (`infra/*`)

**Structure Decision**: Reuses the modular library pattern from `scripts/setup-dev.sh` and `scripts/lib/` to keep shell functions isolated, unit-testable, and maintainable. `.agents/skills/speckit-pr/SKILL.md` exposes the `/speckit-pr` slash command to pairing agents and developers, orchestrating the CLI under the hood. Crucially, the plan integrates `/speckit-pr` into `scripts/lib/skills-audit.sh`, `.agents/skills/dev-onboarding/SKILL.md`, and `docs/ONBOARDING.md` so that new developers and agents automatically audit and discover the new post-implementation capability during onboarding.
